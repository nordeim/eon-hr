## The round's traps

**The stale served process (the §110 family, round two).** The :3200 server had been running since the PREVIOUS session's close (the r98-close build). Every `pkill -f "3200"` matched NOTHING — the port rides in the spawn ENV, not the command line — so every "reboot" died EADDRINUSE while the stale server kept answering, and the live-verify flow mysteriously failed. The cure: kill by the SERVER.JS PROCESS (`pkill -f "standalone/server.js"`), verify `ps` shows zero survivors, then boot.

**The E2E fixture discrimination hole.** A mutation proof's E2E fixture must carry the fix's payload EXCLUSIVELY through the new path — a whole-word atom with a matchable keyword lets the spec pass with the fix reverted.

**The accessible-name leading space.** The snapshot line reads `- tab " AI CV Upload"` — the icon + text label renders a LEADING SPACE in the accessible name; an exact-match regex silently never matches. The tolerant `\s*` form is required.

**The scorer's first-24 keyword cap.** `scoreCv` caps the job's keyword set at the FIRST 24 unique non-stopword tokens — for the System Admin job, "onboarding"/"HRIS"/"training" sit PAST the cap (they appear late in the description). Not a defect — a documented scorer property the fixture design must respect.

**The synthetic-click inertness.** A synthetic `element.click()` (the eval path) does NOT switch the clone's CONTROLLED Radix tabs — the controlled `onValueChange` needs the full pointer-event sequence; the agent-browser snapshot-ref click is the reliable path.

**The guard-clearing payload's leak class.** A mutation-proof E2E fixture that DELIBERATELY clears the extraction guard (so the failing flow still reaches the assertions) will POST its row in the failing runs too — and the never-reached cleanup leaks it into the persistent db/e2e.db, breaking DOWNSTREAM specs (exact-order + zero-state) in LATER runs. The cure: the pre-clean beforeEach sweep (the /assets pattern) — every spec whose payload survives its own failure mode needs it.
