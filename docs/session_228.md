**The exported-`DATABASE_URL` guard's THIRD leg (the server boot).** The guard was known for the Prisma CLI and the `next build` legs; this round the :3200 server BOOT inherited the sandbox's exported `file:/home/z/my-project/db/custom.db` (a nonexistent path) and every API call answered Prisma Error 14 "Unable to open the database file" — the login failed with a 500 while the page rendered fine. The cure: `env -u DATABASE_URL` on the server boot too. The guard now covers all three legs: CLI, build, and boot.

**The E2E-layer stale-served-build (the §110 family, round three).** The playwright webServer runs the prebuilt standalone — a source fix does not reach the E2E until a rebuild. Symptom: the born-green run fails exactly like the mutation. The discipline: REBUILD before every E2E run that follows a source change.

**The fixture-space placement.** A kern-split fixture's word-trailing space must ride INSIDE the last atom (the real Word form `(ation)-2( T)`). Placing it outside fuses the words under the fixed build — and a passing assertion then rides the fragile whole-fused-token prefix match instead of the intended per-word tokens.

**The years-member leak.** A mutation-proof E2E fixture must not carry scoring components that survive the mutation — the "5 years" regex parses split soup too, and its +10 pushed the mutated aiScore to 10, past the `> 5` assertion. Every score component in the fixture must die with the fix.
